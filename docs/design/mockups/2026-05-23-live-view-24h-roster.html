Timeline popover — anchored beside the drawer row

  • Full timeline visible per your decision #1. Photos show single timestamp; videos show start → end with duration in parens.
  • Sage dot for photo, coral dot for video — same colour vocabulary as elsewhere on the page.
  • Sorted by most-recent first, scrollable if > ~8 events.
  • Report button stays — same flow as currently-active card.
  • Auto-flip popover positioning so it doesn't render off the right edge on narrow viewports.

Use case Carl named: bystander correlates against the venue's own CCTV. CCTV at 14:12 shows phone-in-hand; our timeline shows a video at 14:11 → 14:12; the recording was through homefit.studio. Or CCTV shows phone-in-hand at 14:30 and our timeline shows nothing — that recording wasn't through our app.

Implementation notes for the executor

  • Active vs recently-active is one query — get_premises_active_roster(slug, slug, 24) returns both, joined against active_capture_sessions for the currently_active boolean. Web-player splits in JS.
  • Grace period (decision #6) — when currently_active flips false on next poll, hold the avatar on map for ~60s with a slow opacity fade before animating into the drawer stack slot. Mockup doesn't show the animation; live page should.
  • Drawer state on mobile portrait — full 220px width covers ~60% of a 360px viewport, which is fine when expanded. Pill state takes only ~32px when closed.
  • Polygon visible behind drawer — drawer uses backdrop blur, not solid background, so the venue context isn't lost.
  • Currently-active avatar tap — same popover style (Scene 3) but anchored beside the avatar on map. Already covered by item 25's popover state machine; reuse.
