Safe Mode v2 — Enrolment Polish (Phase 2)

Four states / screens covering the Phase 2 changes from docs/specs/2026-05-25-safe-mode-v2-enrolment-polish.md: real-time pose-gated sweep, live quality scoring, manual avatar selection grid, and the avatar-only single-shot mode for when face-rec consent is OFF.

States in this wireframe

  1. State 1 — Sweep start (full mode)
  2. State 2 — Sweep mid-capture (3 of 6 + rejection)
  3. State 3 — Sweep complete: manual avatar selection grid
  4. State 4 — Avatar-only mode (face-rec consent OFF)

Sweep start

Initial frame · before any pose is committed

  • Guidance ring — six radial segments around the face guide. All segments dim coral (18% opacity). Each segment maps to a pose bucket: front, front-left, front-right, left, right, slight-up.
  • Dashed face guide — soft coral dashed circle marks where the client's face should sit. Replaces the prior solid breathing circle (less visually loud while six segments compete for attention).
  • Slot counter top-right — pill chip "0 of 6 captured". New element; the Wave-D editor had no slot counter.
  • Camera flip chip top-right corner — Phase 1 element re-shown here for context. Persisted last-used per device.
  • Cancel top-left — same X chip as Wave-D.
  • Hint text below the ring — first prompt is passive ("Look at the camera to begin") until the first pose is detected. Then switches to active guidance toward missing buckets.
  • No "Start" button — the sweep auto-begins as soon as Vision sees a face. Removes a tap vs Wave-D.
Open question 1 (pose-bucket count). This wireframe uses 6 segments per the spec recommendation. Spec section 10 flags 8 as the alternative. Carl: confirm 6 vs 8 before Phase 2 lands.

Sweep mid-capture

3 of 6 captured · one frame rejected

  • Three segments lit coral — front, front-left, left. Lit segments glow softly (drop-shadow at 55% coral). Three missing: front-right, right, slight-up.
  • Quality badge top-right ("Last slot: 87") — newly-added live feedback. Colour-coded: coral ≥ 80, amber 60-79, rose < 60. The badge displays the most recently accepted slot's composite score (5-component weighted sum from spec section 4c).
  • Hint text derives from which missing bucket is closest to the current detected pose. Implementation: argmin(poseDistance(currentPose, bucketCentre)) for bucket in unfilled.
  • Reject toast (rose-tinted pill) — surfaces briefly (~1s) when a candidate frame is rejected for quality. Shows the actual score so the practitioner understands why. The slot counter does NOT increment.
  • Slot counter live-updates — "3 of 6 captured". No animation on increment; just a flat label change to avoid jitter.
  • No haptic on accept/reject — iOS suppresses haptics during active mic / camera capture (gotcha memory). Visual feedback only.
Open question 2 (quality threshold). Spec recommends 60 as the reject threshold; 42 in the wireframe is well below. The wireframe also shows the rejected score on the toast so practitioners can calibrate — confirm we want to expose the raw number vs a softer "Move into better light" message.
Pose-distance threshold (open question 4). 25° Manhattan sum is the spec default. With 6 buckets ~60° apart, that gives roughly 35° of slop per bucket — generous. Tune in Phase 2 device QA.

Captured angles · 6

Manual avatar selection grid

Sweep complete · full mode (both consents ON)

  • Quality histogram at top — six narrow bars, one per captured slot, colour-coded by quality band. Visual at-a-glance "spread" of how well the sweep went. If the average is < 70 a separate retake-suggestion banner would show above the grid (not pictured here — that's the "low quality" variant).
  • 6-cell face grid (3 wide × 2 tall) — each cell shows the cropped face, a quality-score chip top-right, the pose label bottom ("front-left", "front", etc.), and the frontal star top-left on the default pick.
  • Default selection is the frontal pick (highlighted with coral border + glow). The practitioner can tap any other cell to override; :hover states preview the swap.
  • Confirm (primary coral) — persists embeddings + chosen-frame avatar JPG.
  • Retake (secondary) — discards all six slots and restarts the sweep. No "Are you sure?" modal (R-01).
  • Grid is hidden when avatar consent is OFF — see spec section 3 consent matrix. In that mode (face-rec ON, avatar OFF) the sweep completes silently, embeddings persist, and the screen pops.
Pose-label grammar. Wireframe uses human-readable labels ("front-left", "slight-up") over the spec example ("front-left, 0° pitch"). The numeric pitch is noisy and not actionable for the practitioner; the bucket name is what matters. Confirm.
State 4 — Avatar-only mode
Tap to capture client's avatar

Avatar-only mode

Face-rec consent OFF · avatar consent ON

  • No guidance ring — there's no multi-reference sweep to guide. Just frame the face and tap.
  • No slot counter, no quality badge — single capture. (Internally a sharpness + lighting gate can still reject a blurred shutter press; the spec leaves quality scoring "optional" for this mode.)
  • Centered shutter — large coral-edged white circle, matches the existing Capture screen shutter for familiarity. Active state: scale to 0.95.
  • Shutter hint below the shutter — disambiguates "this is an avatar, not a workout capture". Drops once the user has captured one (not pictured).
  • Camera flip + Cancel chips identical to the full-mode states.
  • No grid afterward — single tap captures, saves to raw-archive/{practice}/avatars/{clientId}.jpg, pops the screen. Acts as the legacy avatar-capture flow.
Consent matrix coverage. The other two combinations are not separate screens: face-rec ON / avatar OFF reuses States 1–2 but skips State 3 (no grid). Both OFF never opens the editor — entry-point widgets show a SnackBar redirecting to the consent sheet.
