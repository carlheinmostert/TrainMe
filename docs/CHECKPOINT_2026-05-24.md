# Checkpoint — 2026-05-24 — Safe Mode Transparency wave + face-rec v2 + capture audit

## The day's big decisions

Six load-bearing decisions surfaced across the wave.

1. **Make Safe Mode publicly observable.** Until this wave the only signal that Safe Mode was protecting bystanders was a coral banner inside the trainer app. The Transparency wave (PR [#433](https://github.com/carlheinmostert/TrainMe/pull/433) phases A-D, then [#443](https://github.com/carlheinmostert/TrainMe/pull/443) per-premises URLs) inverts the asymmetry: anyone at the gym can scan a QR poster or visit `/v/{practice}/{premises}/now` and watch the live recording roster. The page shows a Leaflet map of the enforcing polygon with the practitioner's avatar pinned at the GPS-projected position, plus a recently-active roster pulled from the new `capture_audit_events` table. The poster sits in the gym; the URL is permanent; the practitioner has no way to hide the feature being on.

2. **Replace the "largest bbox = client" heuristic with face recognition.** The original Safe Mode discriminator picked the biggest detected person bbox as the client and blurred everyone else. Real-world it mis-identifies: a child client with a tall parent in frame, a seated client with a standing bystander, a client further from camera than a passerby. Safe Mode v2 (PR [#439](https://github.com/carlheinmostert/TrainMe/pull/439) schema, [#441](https://github.com/carlheinmostert/TrainMe/pull/441) native MobileFaceNet, [#442](https://github.com/carlheinmostert/TrainMe/pull/442) Dart wiring) stores a 2048-byte face embedding per client (gated by the new `safe_mode_face_recognition` consent key), and on each frame runs MobileFaceNet against every detected face, picking the match above a cosine-similarity threshold. The first attempt at this (PR [#423](https://github.com/carlheinmostert/TrainMe/pull/423)) crashed the selfie-capture flow and was reverted same-day in [#426](https://github.com/carlheinmostert/TrainMe/pull/426). The proper v2 implementation took the rest of the day plus a string of small fixes ([#448](https://github.com/carlheinmostert/TrainMe/pull/448), [#450](https://github.com/carlheinmostert/TrainMe/pull/450), [#455](https://github.com/carlheinmostert/TrainMe/pull/455), [#457](https://github.com/carlheinmostert/TrainMe/pull/457), [#458](https://github.com/carlheinmostert/TrainMe/pull/458), [#460](https://github.com/carlheinmostert/TrainMe/pull/460), [#461](https://github.com/carlheinmostert/TrainMe/pull/461), [#463](https://github.com/carlheinmostert/TrainMe/pull/463)).

3. **Mapbox reversal — use what we already have.** First architectural pass on the live page reached straight for Mapbox Static Images API (snapshot pipeline, edge function, R2 caching). Carl caught the inconsistency: the portal premises editor already uses Esri World Imagery tiles via Leaflet, free, no token. PR [#449](https://github.com/carlheinmostert/TrainMe/pull/449) reverted the Mapbox architecture and rewired the live page to Leaflet + Esri to match the editor — vendor-consistent, free, no token to leak. Lesson encoded: check the existing pattern before reaching for a new vendor.

4. **Per-capture audit events, not session-level.** The 24h roster on the live page needs to answer "who recorded in the last 24 hours, where, when?" Could have been derived from `exercises` rows at publish time, but that hides everything mid-session and gives a misleading "no recent activity" feed while a practitioner is actively capturing. The decision (PRs [#459](https://github.com/carlheinmostert/TrainMe/pull/459) RPC + drawer, [#462](https://github.com/carlheinmostert/TrainMe/pull/462) mobile write path) was to write one audit row at the moment of capture (photo shutter / video stop), offline-first via the `pending_ops` queue, surfaced via the anon `get_premises_active_roster` RPC.

5. **R-01 restored on premises.** The premises editor had drifted to a modal popup — direct violation of R-01 (no modal confirmations / no pop-up creation flows, also memorialised as `feedback_no_popups_ever`). PR [#419](https://github.com/carlheinmostert/TrainMe/pull/419) killed the modal and routed to an inline detail page. Then PR [#452](https://github.com/carlheinmostert/TrainMe/pull/452) added the address-autocomplete autoFocus, URL-preview justify fix, and Safe Mode quick-toggle on the premises list.

6. **CI surfaces tightened.** Two quality-of-life CI wins. PR [#453](https://github.com/carlheinmostert/TrainMe/pull/453) added `reg.update()` on service-worker register + on `visibilitychange` — fixes the "Safari serves stale SW bundle for an hour" trap permanently. PR [#454](https://github.com/carlheinmostert/TrainMe/pull/454) gates the iOS-build job behind a `git diff` check that excludes `app/assets/web-player/**` from the impact set, so web-player-only PRs no longer burn the macOS runner; same PR added the `ios-impact` auto-label workflow and the `tools/ios-pending-prs.sh` wrapper that filters the merged-but-not-installed queue.

## Lessons / gotchas

- **Check the existing pattern before reaching for a new vendor.** The Mapbox snapshot pipeline (~250 lines, edge function, R2 caching, token rotation) got built then thrown away when Carl pointed out the portal premises editor was already using Esri tiles. New stack item or spec edit should explicitly call out "what's already in the repo that solves this?" as a pre-flight question.
- **Web-player JS edits MUST bump `web-player/sw.js` comment block** AND sync the `app/assets/web-player/` mirror. Drift-guard CI catches the mirror; nothing catches the SW bump except convention. Future agents are briefed via the always-bump memory.
- **`app/assets/web-player/**` is excluded from iOS-impact detection** in the new `.github/workflows/` filter — the mirror sync no longer triggers macOS builds. Already shipped #454.
- **`COMMENT ON COLUMN ... IS '...' || '...'` is invalid SQL.** The `COMMENT ... IS` clause needs a single string literal, no concatenation. Caught + fixed mid-session.
- **`= ANY (user_practice_ids())` without subquery wrap is also invalid** — already-known gotcha from `infrastructure_gotchas.md`; a fresh sighting bit `get_practice_profile_owner` on the 2026-05-21 PR but only caught + fixed today via [#438](https://github.com/carlheinmostert/TrainMe/pull/438). The pattern is `= ANY (SELECT ARRAY(SELECT user_practice_ids()))` — set-returning functions aren't valid directly on the RHS of `= ANY`.
- **Direct `mcp__supabase__apply_migration` during a wedged Branching state silently desyncs git from server.** Every migration applied this way writes a row in `supabase_migrations.schema_migrations` whose version doesn't match the corresponding `supabase/migrations/*.sql` filename timestamp. Cost today: 11 rows to reconcile manually before the next Branching reset can succeed. Memory rule encoded.
- **The face-recognition pipeline took a revert + a crash fix + ~6 follow-up fixes before stable.** PR #423 → reverted in #426 → crash hardened in #427 → v2 rewrite in #439/#441/#442 → bytea encoding fix in #455 → hard-refuse in #458 → threshold tuning in #460 → cache rehydrate in #461. When the foundational heuristic changes, expect a cascading-fix tail of ~6 PRs.
- **iOS Reduce Motion / debug-builds-crash-without-debugger / RSC function-prop boundary** all got memorialised this wave — three separate "spent more time than expected" debugging chains. Each one's memory entry pays back the cost on the next encounter.
