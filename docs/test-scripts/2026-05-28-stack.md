## Execution approach (from the 2026-05-28 alignment analysis)

The fix is NOT "tweak the handout" — it's extracting SHARED, surface-
agnostic modules consumed by BOTH `lobby.js` and `handout.js`, mirroring
the existing `hero_resolver.js` precedent. Recommended sequence (lowest
risk first):

1. **One token layer.** Collapse the handout's `--brand-*/--surface-*/--ink-*`
   onto the canonical `--c-*` tokens (or a shared `tokens.css`). Preserve
   the `--seal-coral` lock and the `applySkin()` `--practice-brand-*`
   contract.
2. **Adopt the mandated hero resolver in the handout** (`hero_resolver.js`
   + `exercise_hero.js`). Kills the bespoke 64px `object-fit:cover` thumb,
   makes crops match every surface, and delivers item 6 (static
   practitioner-treatment render) for free.
3. **Shared dose/stats formatter** — both surfaces consume
   `api.formatReps/formatHold/formatWeight` + `api.allSetsForSlide` (today
   the handout's parallel logic can show DIFFERENT rep numbers + ignores
   `plan.circuit_names`).
4. **Shared card renderer** (`exercise_card.js`) returning inert markup +
   data-attributes; each surface wraps + attaches its own behaviour. Keep
   mp4 on `data-video-src`, never `<img src>` (iOS WKWebView trap).
5. **Shared get-app block + shared footer/seal** (canonical logo glyph on
   both; promote the seal to the lobby footer).
6. **Referral-slug RPC + real QR** (item 11).

Keep surface-specific: lobby interactivity (observers, video-swap, prep
flash, Start CTA); handout print concerns (`@media print`, native print
bridge, `/me?claim=` route, brand-skin header swap).
