## 6. Live transparency URL should be PER-PREMISES, not per-practice

**Surface:** Web player `/v/{slug}/now`, poster QR encoding, mockup at `docs/design/mockups/2026-05-23-premises-list-with-actions.html` (item 5).

**Issue:** Today the live URL is `/v/{practice-slug}/now` — one URL per practice. But a practice has multiple physical premises with different bystanders, different posters, different ongoing sessions. The poster at "Studio Floor" should NOT show people recording at "Outdoor Court" 10 km away. Bystanders standing at one location only care who is recording AT that location.

**Direction:** The URL becomes per-premises. Carl's proposed shape:
`session.homefit.studio/v/{practice-slug}/{premises-slug}/now`

Each premises needs a `public_slug` of its own (3–40 chars, lowercase, hyphenated; unique within the practice). Generated default from the premises name at create time; owner can rename via the editor.

Cascading impact:
- **Schema:** add `public_slug` column to `practice_premises` (text, unique within practice via `(practice_id, public_slug)` constraint).
- **Poster QR:** encodes the per-premises URL, not the practice URL.
- **`get_live_sessions` RPC:** takes BOTH `p_practice_slug` and `p_premises_slug`. Filters `active_capture_sessions` to that premises only (using existing `premises_id` FK).
- **Web player route:** `/v/{practice-slug}/{premises-slug}/now`.
- **Web player API:** `web-player/api.js` `getLiveSessions(practiceSlug, premisesSlug)`.
- **Page-level "Live view" link** on the premises list (item 5 mockup) loses its meaning as a single practice-wide link — instead each premises row gets its own `Live` button that opens THAT premises' URL. The page-level link in the mockup should be removed or repurposed (e.g. show a small per-venue dropdown). Worth revising the mockup once this direction is agreed.
- **Practice-wide overview** — open question: do we still want `/v/{practice-slug}/now` as a fleet-view for the owner / curious bystanders? Probably yes as a roll-up, but lower priority — the bystander use case is venue-specific.

**Files probably involved:**
- New migration: `practice_premises.public_slug` + unique constraint + RPC param + filter
- `supabase/functions/` — none changed
- `web-player/live.html`, `web-player/live.js`, `web-player/api.js`, `web-player/vercel.json` (route rewrite)
- `web-portal/src/app/premises/[id]/poster/page.tsx` — QR encodes the new URL shape
- `web-portal/src/app/premises/` — slug field added to the editor; default-generate from name
- Tests + mockup updates as a consequence
